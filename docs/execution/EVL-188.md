# EVL-188 — Preserve captured order prices on reopen

## Implemented checkpoint

An open order's saved per-unit `unit` value is authoritative when rendering totals, resuming the order, and entering checkout. Saved product names and modifier text are likewise preserved. Changing the current catalog price, product name, availability, or modifier label/price does not silently rewrite an already captured line. Quantity changes scale the captured unit value. Notes can be edited without catalog lookup.

For newly captured lines, the POS now retains the immutable result from `captureProductLine` (EVL-120), alongside the existing local account fields. The stored capture includes the captured product name, base and modifier totals, per-unit cents, quantity, modifiers and notes. Existing legacy account lines keep their already-captured `unit`, `name`, and `modsText` values unchanged; the app does not fabricate missing version or tax metadata.

Modifier changes to an existing line are blocked with a clear remove-and-readd instruction. Re-adding creates a new capture using the current catalog and makes the price change explicit to the operator. This also avoids trying to infer historical base/modifier splits from legacy lines that only stored a combined `unit` value.

If neither a saved `unit` nor captured cents exist, the line is labeled “Precio por verificar”. Saving the account and checkout are blocked with a repair message; the mutable menu is never used to fill the historical gap.

## Verification

- Component regression seeds an open account with a $50 Americano and a $60 Americano with Avena, changes the current product to renamed, $80, unavailable and changes Avena's current label/price, then opens the saved account. The test checks captured labels and values, quantity adjustment, discount, save, app reload, full payment, and persisted sale line totals/modifier text.
- Component regression verifies that new captures store EVL-120 snapshot values and that missing historical unit values and modifier changes are blocked rather than inferred.

## Remaining gates and limits

- This is the prototype's local account behavior. It does not complete EVL-118 trusted actor authorization or EVL-126 durable persistence/recovery.
- The legacy local record does not contain `catalogPriceVersionId` or a tax policy. No such values are invented here. Full EVL-113 server-compatible snapshots require the reviewed catalog version and tax policy integration.
- Two-device synchronization and payment-provider reconciliation remain outside this issue checkpoint.
