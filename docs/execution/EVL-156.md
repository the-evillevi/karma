# EVL-156 implementation checkpoint

This is a bounded implementation checkpoint for EVL-156, based on the approved palette and interaction contract in [`DESIGN.md`](../../DESIGN.md). It is not a completion or visual-approval claim. Full mapping, integration with EVL-116, and desktop/mobile review remain open.

## Implemented

- Added official shadcn/ui configuration for the existing JavaScript Vite app (`components.json`, `jsconfig.json`, `@` alias) and Tailwind CSS v4 through the Vite plugin. The generated components use the Radix base and JavaScript/JSX output. The two existing HTML entries remain intact.
- Centralized the shadcn semantic color variables and radius aliases in `src/styles.css`, using only the values recorded in `DESIGN.md`. Primary buttons use toasted brown with paper text; outline controls use the stronger primary boundary where the border carries meaning; destructive controls use charcoal/paper. Focus uses a 2px toasted-brown ring with a 2px offset. No dark theme or new hue was added.
- Added generated shared `Button`, `Card`, `Badge`, `Input`, `Textarea`, `Label`, `Select`, and Radix `Dialog` primitives in `src/components/ui`. The Button supports primary, secondary, outline, ghost, link, and destructive variants, a 44px minimum target, visible focus, disabled and busy states, and `asChild`. Form controls have persistent label composition, 44px targets, primary boundary contrast, and visible focus. `Badge` includes neutral, pending, success, and conflict variants. Button and focus-managed wrappers forward refs so Radix keyboard behavior works.
- Replaced kitchen filter buttons, kitchen action buttons, kitchen status pills, and kitchen card wrappers in `src/ComandaApp.jsx` with shared primitives.
- Replaced POS category filters, discount action, order-save/send/cancel actions, and checkout CTA in `src/PosApp.jsx` with shared Buttons. The empty-order CTA remains keyboard-operable and still calls the existing validation/toast path.
- Continued the POS migration across login user selection, navigation and sync controls, order-type filters, 44px labeled quantity controls, and open-order cards/actions with semantic preparation and synchronization badges. Inactive users and restricted destinations remain operable so their existing explanatory messages still appear.
- Replaced the existing POS confirmation overlay with the Radix Dialog. Existing state callbacks remain authoritative; labels are associated with fields, field errors are announced, Escape closes the uncommitted dialog, focus returns to the invoking control captured on open, and the close control meets the 44px target.
- Migrated checkout steps, tip/method choices, split-payment actions, amount fields, navigation and outcome actions, and order summary panels to shared Badge, Button, Input, Label, and Card primitives. Selected choices expose `aria-pressed`; each payment amount has a method-specific accessible name. Existing payment validation and app callbacks remain authoritative.
- Migrated menu category filters, product rows/statuses, search, and the product editor to shared Button, Badge, Card, Input, Label, and official shadcn Select primitives. Fields have persistent labels, selected filters/rows expose state, and the product listing/editor wraps at narrow content widths. Save still uses the existing app state and persistence path.
- Migrated inventory tab/action/filter controls, low-stock selection, stock/movement statuses, recipe cards, and the wide stock/movement tables to shared primitives. The wide tables remain horizontally scrollable inside their card on narrow content widths.
- Migrated report date filters, export action, KPI/summary cards, sale status and sync badges, and the sale list actions. Migrated configuration tabs, user rows/editor, role/permission selections, settings cards, backup/sync actions, and preference toggles to shared controls; switches are visibly labeled and controlled by existing feature flags.
- Changed the shared dialog close button's screen-reader name to “Cerrar”.
- Added `components-demo.html` as a small component variant story with button, badge, card, and dialog states. The demo is available at `/components-demo.html` while Vite runs.
- Added repeatable checks for dialog keyboard open/dismiss/focus restoration, the disabled/`aria-busy` button contract, input label/error association, menu editor save with keyboard-operated Select, seeded open-order checkout through successful payment, inventory filters/recipe view, report range selection, user editing, persistent settings-toggle state, and a Comanda ticket status advance persisted in offline local storage. The POS integration test also signs in using the seeded cashier PIN, opens the real role-warning dialog through restricted navigation, and verifies Escape returns focus to the invoking button.

## Remaining migration and review gates

This checkpoint does not include the shadcn mappings for Tabs/ToggleGroup, AlertDialog, Sonner, Table/ScrollArea, Alert, Avatar, Progress, InputOTP, Separator, Sidebar, Sheet, or Drawer. Select is used for menu editing and Switch for preference toggles. Use remaining primitives only where they fit the existing business flow; do not replace a flow solely to match a component inventory. EVL-158 owns the broader responsive shell and mobile navigation; the fixed-width shell still needs that follow-on review.

Before calling EVL-156 complete, reconcile dependencies/configuration with EVL-116, continue replacing duplicated controls in the remaining modules, run representative POS, inventory, recipe, open-order, report, configuration, checkout, and Comanda flows, and verify rendered desktop and mobile layouts with root. Record actual visual findings rather than treating the demo or build as visual evidence. Keep the Linear issue open until those gates are met and team acceptance is recorded.

## Migration note for new UI

Import shared components from `@/components/ui/*`; use `Button` variants and `Badge` status variants before writing new repeated style objects. Compose cards from `Card` primitives and use `Dialog`/Radix focus behavior for modal work. Use `cn` from `@/lib/utils` to combine Tailwind classes. Add new semantic colors and radius decisions to `DESIGN.md` first, and keep app-specific event/state logic in the app component. New controls need persistent labels, keyboard focus, disabled/loading/error states, and a test or demo covering their user-visible states.
