# EVL-125 — Manual sale refunds and voids

This bounded checkpoint adds a manager/owner report flow for recording money already returned manually. It appends a separate compensation event with stable command identity, selected original payment allocations, actor, UTC time and mandatory reason. The original completed sale, line snapshots, original tender/change, payment nets, totals, preparation link and tip remain intact. Full void is available only before any refund and compensates the whole collected total; partial mixed-method refunds require an explicit original payment selection. Further refunds cannot exceed the remaining total or the chosen payment's remaining net amount. Returned cash change is never treated as money still available to refund.

Confirmation checks the current canonical refundSaleWithReason permission and scoped verified identity, compares live and persisted source snapshots, validates payment/history reconciliation and stores the event before announcing success. Same-command retries recognize the original event and different-content retries fail. Failed storage preserves the source and stable dialog identity. The write preserves newer unrelated local state and refreshes live order/history/settings/folio state so the next ordinary save cannot erase those saved changes.

Reports display original gross collections, refunds/voids and net after those events separately, with derived partial/full refund labels and retained audit detail. Refund events are filtered by their own date, including corrections to older sales; a day can consequently have negative net collections. External card/transfer return records remain manual and unverified. No terminal request is sent. No stock restoration or whole kitchen-ticket cancellation is invented: inventoryCompensation remains pending until EVL-129 can reverse recorded consumption exactly once. Credit-backed sales require their own repayment/correction policy in EVL-135.

This remains one prototype browser-local record. EVL-126 durable transaction, remote authenticated versions/conflicts and cross-device exactly-once behavior, EVL-129 inventory compensation, and EVL-130 complete reconciled exports remain open acceptance gates. These limitations are displayed in the refund dialog/history. No main merge, Linear write, real-account provisioning or deployment is included.
