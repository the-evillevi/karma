# EVL-158 — responsive POS shell and mobile navigation

## Scope and base

This is an implementation checkpoint on the EVL-158 branch, stacked on the reviewed EVL-156 work and integration commit `5f2fe86`. The integration base contains SalesStation and the four HTML build entries. Work here is limited to the POS shell, navigation, responsive module containers, and viewport regression coverage. SalesStation actions and order state remain owned by the catalog implementation.

The desktop navigation now uses shadcn Sidebar. Below 768 CSS pixels it becomes a sticky mobile bar with a shadcn Sheet containing the same navigation, open-order count, connection and pending-sync state, sync controls, kitchen link, and current-user action. Short landscape sheets scroll to their footer controls. Choosing a navigation item closes the Sheet and returns focus to the menu trigger. Sidebar colors use the values already defined by the Karma semantic tokens in `src/styles.css`.

The POS content column can shrink without widening the document. Module padding contracts at tablet and phone widths, and wide inventory/report tables scroll in their card containers. The cart and module business actions are unchanged.

## Evidence recorded

- Reproduce the responsive browser checks with `pnpm exec playwright test --config scripts/responsive/playwright.config.js`.
- `pnpm build` passed after the generated Sheet and Sidebar were added; it emitted POS, Comanda, offline-demo, and component-demo entries.
- The Playwright mobile Sheet test passed at 390×844: navigation and status context were present, selecting Inventory closed the Sheet, focus returned to the trigger, and the page had no horizontal overflow.
- The viewport Playwright matrix passed at 1280×900, 1024×768, 768×1024, 667×375 (landscape phone), 430×932 (large phone), 390×844, and 320×640. It checks document and main-column overflow, current-order visibility, keyboard opening/focus, and Escape focus return at phone sizes.
- Root review identified that station keyboard focus as part of this responsive scope. The Alt+ArrowDown path now waits until the cart is rendered before moving focus into it; Escape returns focus to the cart toggle. Touch opening remains on the toggle without an unexpected focus jump.
- The 390×844 primary-flow browser pass covers open orders into checkout/payment, menu search, inventory/recipes with a horizontally scrollable stock table container, report sale-detail Dialog bounds and focus restoration, user editing/configuration, and the Comanda entry. A narrow menu-search row initially exposed a 9px internal overflow; it now wraps its action below the search input when needed.
- Product editing remains in the existing Dialog and was checked against 390×844 and 320×640 bounds. Current-order quantity/remove controls are 44×44 CSS pixels; tests add a seeded line, increment it, and check for horizontal overflow at both widths.

These checks exercise a seeded browser prototype. They do not establish operator acceptance or final visual sign-off.
