# EVL-155 — Operator-selected split quantities

The open-account split dialog now lets the operator choose an integer quantity from each captured order line for the new account. Zero leaves that line in the original account. The dialog recalculates and displays both accounts' line allocations, subtotals, discounts, and totals before confirmation. Invalid quantities, an empty selection, and moving every unit to the new account are blocked in the UI.

The split continues to use captured unit-price cents and conserves the original discount in integer centavos. Partial lines retain their captured product, modifier, note, and tax snapshots with updated quantities and line totals. Existing confirmation-time authorization and source-version checks, latest-local-record patching, stable operation identity, and retry behavior remain in the flow. Reusing a saved operation succeeds only when the requested selection normalizes to the stored allocation and the linked child has the matching source and operation lineage. Both resulting accounts retain their shared preparation linkage; the split does not create or duplicate a kitchen ticket.

Focused verification passed: 17 mounted split-dialog regressions cover operator-selected whole-line and partial quantities, zero/whole-account/malformed/over-available selections, captured pricing and snapshots, stale-source rejection, failed-write retry, identical-operation idempotency and changed-allocation rejection, unchanged shared preparation, and the existing split lifecycle. The full domain suite passed (77 tests), the component suite passed (86 tests), Prettier's repository check passed, and both production and PWA builds completed.

This implements the local operator-selection slice. Durable cross-device transactions and version conflict reconciliation in EVL-126, plus granular compensation in EVL-129, remain required before production acceptance.
