# EVL-130 report export checkpoint

The first bounded module generates UTF-8 BOM CSV evidence from explicitly selected local sale, payment, and compensation records. It uses the reviewed compatible adapter to retain captured net cash, tender/change, tips, payment identity, refund allocations, and original actor. Text cells neutralize spreadsheet formulas and CSV delimiters; no PIN, session, roster, customer profile contact, or privileged credential is exported.

Original legacy display dates remain recorded text with blank real-date columns and an explicit warning. ISO UTC facts are rendered in the supplied validated branch time zone. No simulated day offset is converted into a fabricated date; no local sync label is treated as proof of a server receipt. The file is a local sales-evidence export, not a complete backup or verified accounting close.

The builder and current-role-gated actual CSV download are implemented. New checkout records capture UTC occurrence timestamps. Reports and ticket details hide after current permission loss. Root review fixed refund reason/payment/completeness evidence and legacy date rendering. Real period/custom date range filters and reconciled dashboard totals remain open; the file labels the existing prototype selection without certifying it as an accounting period. Do not publish this as full EVL-130 acceptance.

Three domain regression cases passed for exact net payment/change, branch midnight, original unknown dates, refund identity, source immutability, inconsistent captured amounts, invalid zones, formula escaping and CSV quoting. Scoped TypeScript passed.

Actual Chromium saved a CSV and an independent CSV parser verified its aligned net/tender/change/tip columns. Root29 screen cases, three domain cases, types/lint/builds and zero newly introduced medium+ source findings passed. See reviews/EVL-130-export.md.

## Real-period domain checkpoint in progress

`report-period.ts` resolves explicit local branch times to UTC, uses real branch-calendar boundaries for today/seven/thirty days, and refuses impossible or repeated clock times unless the caller chooses their occurrence. Custom end times are exclusive. Legacy display labels and impossible normalized dates remain unknown. Financial totals use each sale/return's own event time: a refund today for an older sale can produce negative net receipts today. Tips remain separate from gross receipts, cancellation captures do not count as receipts, and unknown dates/methods remain visible as unresolved evidence rather than guessed values.

Four domain tests, scoped types and lint passed. This module is not wired into the Reports screen yet; the published CSV draft still labels its prototype relative-day selection. Do not claim real/custom period UI acceptance until wiring and root review pass.
