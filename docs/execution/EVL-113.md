The helper's `applyEventBatch` builds one immutable command-batch document and applies its events to a cloned in-memory projection. Identical retries of the same `commandId` and complete ordered event batch are no-ops; changed batches or mixed metadata fail before projection changes. The storage layer should persist that single batch document as the commit point and derive projections by replay; this branch does not implement durable storage. TypeScript contracts are preparatory and not compiled by the current JavaScript build. No hardware, printer, inventory integration, or runtime POS regression is claimed as accepted.
