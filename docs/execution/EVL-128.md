# EVL-128 · Typed manual inventory ledger

## Implemented in this slice

Inventory balances now come from a typed local ledger using integer base units: grams (`g`), millilitres (`ml`), and pieces (`pz`). Kilograms and litres convert exactly to their base units, quantities are limited to 32 characters and three decimal places, and fractional pieces or unsafe totals are rejected.

The POS can record positive stock entries, positive waste quantities that reduce stock, signed manual adjustments, and audited low-stock threshold changes. Each event stores a stable command ID, actor, timestamp, reason, item revision, unit and quantity snapshots, and an explicit local synchronization state. The current role and latest stored item revision are checked at confirmation. Storage failure leaves the form and its command identity available for retry; a successful retry produces one event.

The seed catalog’s current balances are written once as explicit synthetic opening entries. They are marked unverified and require a physical count. The old text-only demonstration movement history remains visible as clearly labeled fixture data and does not affect ledger balances.

Dueña and Encargado can create, edit, and archive catalog items. Creation requires an explicit real opening count (zero is allowed) and a threshold; it records the operator, time, and reason. Edits append before/after metadata snapshots while preserving the base unit and every prior name/unit snapshot. Archiving is allowed only at zero stock, and leaves the item and its full history visible as archived. Every catalog write checks the current role and latest catalog revision, stores before success, and retains the same command identity if the local write fails so a retry cannot duplicate the change. Cashier inventory remains queryable and read-only.

## Verification

- `src/inventory/inventory-ledger.test.mjs` checks exact conversions, integer base-unit math, opening balances, movement signs, threshold changes and retry identity, revision conflicts, unsafe values, audit-text integrity, catalog create/edit/archive history, unit-migration rejection, and rejection of unknown stored fields.
- `src/inventory/inventory-ui.test.jsx` exercises opening-ledger initialization and reload, stock-low thresholds, typed entries, actor/time/reason capture, fractional piece rejection, role changes, stale item revisions, failed-write retry, manager authorization, cashier read-only access, and preservation of newer POS records.
- `src/inventory/inventory-catalog-ui.test.jsx` exercises real positive and zero opening counts, editing without rewriting past entry snapshots, reload, archived stock visibility, refusing to archive a positive balance, idempotent failed-write retry, authorization changes before confirmation, and stale catalog rejection.
- `pnpm test:domain`, `pnpm test:components`, `pnpm build`, and `pnpm build:pwa` are the scoped project checks for this change.

## Remaining acceptance gates

- These records are local-only. Cross-device synchronization, server authority, durable conflict resolution, and retry acknowledgement remain dependent on EVL-126 and EVL-129. `pending` means locally recorded and awaiting synchronization; it does not mean a remote write succeeded.
- Recipe consumption and automatic inventory deductions are not implemented. The recipe screen remains informational and never changes stock.
- The synthetic opening balances must be replaced or confirmed by a physical stock count before the ledger is treated as verified business history.
