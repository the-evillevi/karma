# EVL-114 execution record

## Scope and artifacts

This checkpoint adds a Vite/React offline demonstration at `/offline-demo.html`, RxDB/Dexie local collections for immutable command batches and server receipts, a Supabase append-only command-batch migration, and a local-only fixture/bootstrap script. The decision and tradeoffs are in [ADR-001](../decisions/ADR-001-offline-first-storage.md). The production app is not migrated to this storage layer in EVL-114.

The batch row is the sole server commit point. One `command_batches` insert contains an envelope and ordered event array, so PostgreSQL either accepts the complete batch or rejects it. The demo writes to RxDB before network access, holds the same batch through reload, and retries after reconnect. A repeated `command_id` is accepted only if normalized envelope/event contents match; a changed batch is a conflict. No payment provider or card data is included.

## Current authorization boundary

The prototype checks branch membership, a logical device ID, capability, role, and one server lease for cash commands. It limits supported event types, schema version, IDs, batch count, and serialized size. This is not physical device attestation: another browser using the same credentials can copy the logical device ID and lease. Offline revocation is observable only after reconnection; local wall-clock expiry is not a trusted clock. Do not describe these prototype checks as production authorization. EVL-118 must add enrollment/session binding, final role/action rules, and revocation behavior.
