# EVL-153 · Read-only local change history checkpoint

## Implemented in this slice

Reports now has a separately loaded **Historial de cambios** view. It projects validated inventory movements, item catalog create/edit/archive events, and recipe publication events from the existing local ledgers. The view preserves each recorded event ID, entity, action, original actor and timestamp, reason, source revision, and local synchronization/provenance label. Inventory movement before/after balances are reconstructed from the append-only movement sequence; catalog and recipe field snapshots are compared to show changed fields. The view only reads the mounted scoped POS state and does not initialize seed balances or write to storage.

Operators can filter by inclusive branch-calendar dates, entity, action, and original user. The time zone is explicit; date filtering uses only strict round-tripping UTC instants captured in the source event. Display-only dates and malformed timestamps are not converted into audit times. Corrupt source ledgers or inconsistent histories fail closed. Current `viewReports` access controls the screen, and loss of that permission unmounts the view.

The current local schemas provide item archive events and recipe publication/update events; they do not provide recipe deletion events. They contain no remote versions or conflict-resolution records. The view says so directly and returns no invented conflict entries. Local browser storage is not a cryptographic tamper-evident server log; this screen reports the validated local ledger evidence only.
