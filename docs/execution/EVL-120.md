# EVL-120 checkpoint: modifier domain and line capture

## Delivered in this preparation checkpoint

`src/catalog/catalog-domain.mjs` now validates modifier groups as active/inactive reusable records and provides pure append-audit commands:

- `modifierGroup.create`, `modifierGroup.edit`, `modifierGroup.reorder`, `modifierGroup.setActive`
- `modifierOption.create`, `modifierOption.edit`, `modifierOption.reorder`, `modifierOption.setActive`

Selection configuration is stored on each group's `selection` record with `required`, `multiple`, `min`, `max`, `defaultOptionId`, and `defaultProvenance`. Group edit changes those together. Option additions require an explicit price effect in integer MXN centavos; this implementation adds no business prices. Deactivating an option cannot leave the group's minimum or default pointing at an inactive option. The catalog seed's existing groups were marked active while all existing options, prices, and selection defaults were preserved.

Group `selection` may also declare a preparation measure using `unit` and positive-integer `defaultQuantity`, such as `unit: "oz", defaultQuantity: 2`. This is schema and behavior support only: the seed does not claim which products require espresso or that two ounces is an approved recipe. Any production default must be validated by the business owner before the catalog gate opens.

`captureProductLine(catalog, request)` validates the active product/category/groups, applies configured default options when the caller omits a group's selection, enforces active option IDs and group min/max, and returns a frozen snapshot. The line copies product and option IDs/names, MXN-centavo base/modifier/unit/extended amounts, preparation quantity/unit where configured, notes, and an optional tax snapshot. The accepted tax snapshot shape is `{ rateBasisPoints, amountCents, currency: "MXN", source }`; this function preserves that supplied snapshot and does not calculate tax. All arithmetic is checked against JavaScript's safe integer range. Later catalog edits do not mutate previously captured lines.

`src/catalog/order-line-adapter.mjs` converts that richer capture to the reviewed EVL-113 `OrderLineSnapshot` field names. It requires explicit `lineId`, `catalogPriceVersionId`, `taxRateBasisPoints`, and `priceIncludesTax: true`; it never invents a catalog price version or tax rate. It places the base catalog price in `unitPriceCents` and each option's added cents in `modifierSnapshots[].priceDeltaCents`, so an order consumer adds the modifier charge once. It also maps product/modifier labels and notes to snapshot fields. The captured tax amount is not represented by the current EVL-113 line contract; the adapter preserves the caller-selected rate/inclusion policy only. The optional `preparationMeasurements` field is a documented extension and is not part of the current shared TypeScript contract, so foundation integration must explicitly adopt it before relying on it.

The source contract was read-only at foundation worktree commit `115c6386c54a19e0f8d398fcfa9d3460f2123fd5`. No foundation source or reducer code is copied into this branch. `src/catalog/fixtures/order-line-snapshot.contract.json` pins a synthetic expected shape from that interface. When the reviewed EVL-113 consumer checkout is available, the optional integration test imports its real `validateLineSnapshot` via `KARMA_113_ORDER_DOMAIN_MODULE` and validates the generated line and post-catalog-edit snapshot. For example:

```sh
KARMA_113_ORDER_DOMAIN_MODULE=/path/to/karma-foundation/src/domain/order-domain.js node --test src/catalog/order-line-adapter.test.mjs
```

The test verifies a synthetic 6,900-cent base plus a 1,000-cent milk modifier produces 7,900 cents exactly once and that later product/option edits leave the captured order line unchanged. Without the external checkout, fixture-shape and domain tests still run; the real-consumer test is skipped.

## Validation

Run:

```sh
node --test src/catalog/catalog-domain.test.mjs scripts/catalog/catalog-normalizer.test.mjs
node scripts/catalog/normalize-seed.mjs --check
```

Synthetic tests cover reusable group/option create/edit/reorder/deactivation, required/single/multiple/default rules, rejection of duplicate product group references and inactive/out-of-range selections, centavo additions and overflow, default-ounce metadata, charge/name/note/tax snapshot copying, and immutability after catalog edits. No user-provided or source-derived modifier data has been added.

## Remaining acceptance gates

This is EVL-120 domain preparation only. EVL-116 must provide the reviewed app/runtime integration point before adding UI controls. EVL-118 must enforce trusted roles and durable audit. EVL-126 must define storage/synchronization and conflicts. The runtime adapter and current POS do not yet render or persist modifier editing, selection validation, notes, ticket/comanda details, or tax snapshots. Printer/comanda output depends on EVL-124; inventory linkage depends on EVL-129. Existing open/closed order persistence must carry these immutable snapshots and satisfy EVL-188. The seed remains demo-only until the source and Carlos validation gates are resolved.
