# EVL-129 checkpoint A — recipe ledger and consumption planner

This checkpoint adds the validated recipe domain in `src/inventory/recipe-ledger.mjs`. Recipe publication requires explicit product IDs and inventory item IDs. It snapshots product and inventory names, type, units, source provenance, and revisions; modifier effects are keyed by the exact `(groupId, optionId)` pair. An operator must explicitly select recipe, finished-piece, or no-stock control. Modifier mappings explicitly choose no stock effect, additions, or substitutions. Base quantities convert through the inventory ledger to integer `g`, `ml`, and `pz` units.

The preview shows the base quantity and a separate stock projection for every configured modifier. It reports missing mappings, insufficient balances, unverified source catalogs, unverified stock counts, and classification mismatches without blocking order flow. No product name or recipe fixture is automatically mapped to an inventory item. The current prototype catalog and synthetic opening balances remain unverified, so they cannot become a successful automatic-consumption source through this code.

`planPreparationConsumption` accepts captured order line IDs, product IDs, quantities, and modifier IDs, and returns a revision-guarded candidate with immutable recipe snapshots and movement allocations. It does not write inventory. Its `applicationState` starts as `not_applied`; there is no checkout hook, kitchen SEND hook, or local write claiming a successful deduction in this checkpoint. A future application boundary must commit the operation and all inventory movements atomically at SEND, with an authoritative current actor and idempotency key. Checkout must not call it.

`planConsumptionCompensation` requires a committed source-consumption record and calculates inverse quantities from that record's actual allocations. It never loads the live recipe. This domain helper is still a planner: it does not write the reversal. EVL-126 must provide the durable transaction, source-revision compare-and-write, and cross-device exactly-once contract before SEND consumption or cancellation/refund can be enabled.

Validation in this checkpoint: `node --test src/inventory/recipe-ledger.test.mjs` (6 tests passed). The actual configuration UI and operator reload/retry flow have not yet been implemented; this checkpoint is not EVL-129 acceptance or a production-ready inventory integration.
