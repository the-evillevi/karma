# EVL-139 discovery/codec review with fixes

Reviewed 2026-09-29 against EVL-139 and the current EVL-114 batch contract. Current official Chrome, WebKit and Capacitor sources were checked for platform claims.

## Findings resolved

- Peer command uploads would violate the current actor/device RLS boundary. Originating actors retain their own server outboxes; peer ACKs never clear backend-pending commands. Cross-actor relay requires a separately reviewed signed endpoint.
- Capacitor desktop support was implied. The selected route is iOS/Android; desktop hosting/estimation remains a separate unknown.
- Codec envelopes lacked required branch/lease IDs and derived event IDs. Validation now matches the current offline batch shape.
- Sparse arrays could encode invalid JSON and deep nesting could exhaust recursion. Both are bounded/rejected, with regression tests.
- Loose timestamps accepted non-ISO dates. Canonical valid millisecond UTC timestamps are required.
- Root added expected branch/lease comparisons to HELLO and branch checks to transferred batches.

## Summary

No blocking findings remain in the bounded discovery/codec artifact. Root ran all 20 codec/domain tests and diff checks. Code validates shapes only; it does not authenticate peers, encrypt, persist, transport or apply commands. Root rebased onto reviewed EVL-114 `074f814`, confirmed its receipt/actor boundaries and documented its narrower POC event allowlist. Actual hardware and final production permissions/integration remain open.

## Acceptance criteria

- Partially met: sourced platform matrix, versioned messages/state/error draft, bounded deterministic codec and concrete mobile native route/estimate.
- Not met: actual target device go/no-go, two-device offline order transfer, observed duplicate handling over BLE, cryptographic pairing, distance/permissions/battery evidence and native integration. EVL-139 stays open; EVL-140 has not started.

Recommendation: preserve a draft discovery checkpoint and retain physical and foundation acceptance gates.
