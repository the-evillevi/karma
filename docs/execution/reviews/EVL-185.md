# EVL-185 root review and fixes

Reviewed a53d707 and 7fe4b88 against the actual Linear acceptance criteria. The app now stores preparation tickets independently from unpaid accounts; payment removes an unpaid account without deleting kitchen work. Tickets retain their folio, origin, lines, modifiers, notes and preparation status across both app reloads. Delivery and reasoned cancellation remove tickets from the active queue.

## Findings fixed

- Critical: a stale kitchen card could overwrite fresh storage and restore cancelled work or lose a newly queued ticket. Comanda now rereads storage at the action boundary, checks the rendered expected status, and advances only the matching fresh ticket; otherwise it resyncs without writing. The regression changes storage after render and preserves both the cancelled ticket and the new ticket.
- Critical: checkout captured its source only when payment registration started, allowing a changed account to be charged using old checkout lines. Checkout now captures the source when checkout opens and compares both current state and persisted state before committing. Regressions cover open accounts and saved station orders.
- Integration fix: the EVL-116 kitchen update gate still used the old unpaid-account collection. The merged guard uses active kitchen tickets, so paid unfinished work blocks reload and delivered/cancelled tickets do not.

## Independent evidence

Root combined integration bf79fc4 passes 17 component tests, 54 unit tests with no skips, and all four Vite entry builds. The paid-ticket cases also assert that unfinished work blocks a PWA update and delivered work releases the gate. Paid-ticket cases cover queued, preparing, ready and delivered status, duplicate payment clicks, both app reloads, and retained ticket contents. The stale-card and changed-checkout regressions pass.

## Acceptance limits

The reported paid-kitchen disappearance is fixed in the actual seeded app. This is browser storage behavior; EVL-118 trusted authorization and EVL-126 durable production storage remain open. Cancellation currently checks the demo role at both action boundaries and records reason, actor and timestamp, but is not yet trusted server authorization. Physical printer acceptance belongs to EVL-124. Cross-tab writes are not a production transaction protocol. The issue remains open until those foundation gates and browser acceptance are met.
