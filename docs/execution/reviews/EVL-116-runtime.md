# EVL-116 typed runtime and update control review

Root reviewed Luna High `df4ec46` against EVL-116 criteria and the existing EVL-113/114 behaviors. The domain and command-sync implementations now execute as strict TypeScript, retaining JavaScript import shims. Application roots contain a sanitized error boundary and a manual waiting-worker control. The control blocks unknown state, checkout, order capture, dialogs, menu/user edits and report details; an explicit confirmation is invalidated by any safety-state transition, including an unsafe-to-safe round trip while activation runs. It does not force other tabs to reload.

Root requested editor/detail guards and a safety revision counter during review. Root also strengthened the positive activation browser check to wait for an actual restarted document after confirmation, rather than only checking a button that was already visible. This stronger check passed in the combined app. A thrown canary containing an email and secret text is not displayed by the error UI.

Independent foundation `pnpm check` passed: format/lint/strict types, 19 unit tests, standard/PWA builds, bundle scans and the browser offline-restart/update/redaction test. The combined integration check passed with all 51 discovered domain/catalog/normalizer/update/sync tests, ten component/app flows, four-entry builds and the PWA browser proof. Root's added component assertions verify menu edits and checkout report blocked update state, and a completed menu save returns to safe state. The duplicate typed test invocation was removed from the combined check because discovery already includes those tests.

The first independent hosted run passed seven cases and exposed a diagnostic regression on revoked-device revalidation: denial was enforced, but a bare controlled Error was categorized as unknown. Luna fix `331a87b` supplies allowlisted denial codes, keeps messages sanitized and strengthens the regression to check removed cached authorization and a disabled capture button. Root source rereview and a full independent hosted run then passed all eight actual browser/RLS cases. No POC schema was changed. GitHub quality run `36671587292` passed for `df4ec46`.

Acceptance remains partial for whole-app coverage: legacy JS/JSX is intentionally unchecked, production credentials/device binding and durable application storage remain EVL-118/126 work. The reachable isolated demo preview is recorded separately in `preview.json`; backend fixtures do not ship there. This checkpoint is sufficient to start secure-access work without claiming production readiness or marking EVL-116 fully complete.
